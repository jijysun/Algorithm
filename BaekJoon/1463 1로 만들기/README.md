# 문제 소개

문제 사이트 링크 → 없어용

정수 X에 사용할 수 있는 연산은 다음과 같이 세 가지 이다.

1. X가 3으로 나누어 떨어지면, 3으로 나눈다.
2. X가 2로 나누어 떨어지면, 2로 나눈다.
3. 1을 뺀다.

정수 N이 주어졌을 때, 위와 같은 연산 세 개를 적절히 사용해서 1을 만들려고 한다. 연산을 사용하는 횟수의 최솟값을 출력하시오.

**입력**

첫째 줄에 1보다 크거나 같고, 106보다 작거나 같은 정수 N이 주어진다.

**출력**

첫째 줄에 연산을 하는 횟수의 최솟값을 출력한다.

입출력 예시 

- 2 → 1
- 10 → 3

# 풀이 과정

- 처음엔 Greedy로 접근했다. 우선순위를 /3 → (-1 후 /3) → /2 → -1 로 잡았다.
- 주석으로 22와 43을 손으로 돌려보니 /2 보다 (-1, /3) 이 유리했다.
    - 거기서 "-1, /3 이 항상 더 좋다"로 일반화했다. 16분에 제출.

```cpp
#include <bits/stdc++.h>
using namespace std;

int dp [107];

/*
- 제한사항 숫자 베끼기: 1<=n <= 106인 정수
- 내 접근의 연산량 = ?  매번 약 4번의 if * 최대 106번이어서 추분     → 1억/초 기준 통과 여부 O/X
- 상태와 전이를 한 문장으로 - 상태: 초깃값 n . 전이: 나눌 떄 마다 (상태와 전이를 어떻게 표현해야 할 지 모르겠어)
- 예시 1개를 손으로 돌리기 -> 주석으로 돌린 것에서 검증

 */

int main ()
{
    int n = 0, answer = 0;
    cin >> n;
    while (true)
    {
        if (n%3 == 0)
        {
            n=n/3, answer++;
        }
        else if ((n-1)%3 == 0 )
        {
            n = (n-1)/3, answer+=2;
        }
        else if (n%2 == 0)
        {
            n=n/2, answer++;
        }
        else
        {
            // -1 하기
            n-=1, answer++;
        }

        if (n == 1)
        {
            break;
        }
    }
    cout << answer << endl;

    // 연산을 사용하는 횟수의 최솟값을 출력
    return 0;
}
```

# 결과 & 근거

- 최소 반례는 N=16인 걸 깜빡해서 틀렸다.
- 전이가 숫자를 크게 점프시키고 도착점의 품질을 즉시 판단할 수 없으므로 Greedy가 성립하지 않는다.
- 체크리스트의 연산량(3 × 10^6)은 DP 기준으로 정확했으나, 코드는 O(log n) Greedy였다.
    - dp 배열을 선언만 하고 쓰지 않은 것이 그 증거다. 체크리스트와 코드 구조를 대조하는 습관 필요

```cpp
#include <bits/stdc++.h>
using namespace std;

int dp [107];

/*
- 제한사항 숫자 베끼기: 1<=n <= 106인 정수
- 내 접근의 연산량 = ?  매번 약 4번의 if * 최대 106번이어서 추분     → 1억/초 기준 통과 여부 O/X
- 상태와 전이를 한 문장으로 - 상태: 초깃값 n . 전이: 나눌 떄 마다 (상태와 전이를 어떻게 표현해야 할 지 모르겠어)
- 예시 1개를 손으로 돌리기 -> 주석으로 돌린 것에서 검증

 */

int main ()
{
    int n = 0, answer = 0;
    cin >> n;
    dp[1] = 0;

    // dp[x] = x를 1로 만드는 데 필요한 최소 연산 횟수
    for (int i = 2; i <= n; i++)
    {
        // 1 빼기
        dp[i] = dp[i-1] + 1;

        if (i%2 == 0)
        {
            dp[i] = min (dp[i], dp[i/2] + 1);
        }

        if (i%3 == 0)
        {
            dp[i] = min (dp[i], dp[i/3] + 1);
        }
    }

    // 연산을 사용하는 횟수의 최솟값을 출력
    return 0;
}
```

너무 약한 DP를 위해 

DP 판별 방법

1. 무엇을 묻는가?
    - 최소값 / 최대값 / 경우의 수 / 가능 여부
    - "경로 자체를 전부 출력"이면 DP가 아니라 백트래킹
2. 최적 부분 구조, Optimal Substructure
    - 전체 최적해가 부분 문제의 최적해로 조립되는가
    - "지금 선택이 다음 단계의 선택지를 제약하는" 구조
3. 중복 부분 문제
    - 서로 다른 선택 경로가 같은 부분 문제에 도달하는가
    - 동일한 작은 문제가 계속 발생하는가.
    - 이게 단순 재귀와 DP를 가르는 핵심!

실전 신호에서는

- 제한 사항이 작거나
- 각 단계에서 유한한 선택지 중 하나를 고른다던가
- 완전탐색을 떠올렸는데 지수 시간이 발생한다던가 (중복계산이 존재한다는 뜻)
- Greedy 비교 함수를 한 문장으로 쓸 수 없다던가 (DP는 가능)
- 보상/가치가 여러 차원, Greedy는 전순서가 없으니 불가
- 답이 구성이 아닌, “값”
- 굳이 점화식을 세우려고 한다기 보다는 BottomUp 이나 TopDown 먼저

### 알고리즘 분류

- DP (1차원)
- Bottom-up DP
