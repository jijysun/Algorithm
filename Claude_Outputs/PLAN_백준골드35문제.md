## 2. 반드시 지켜야 할 제약 2개

### (1) 지문 원문은 긁어올 수 없다

WebFetch 는 **출처 원문을 125자 이상 인용하지 않는다.** 실제 응답:

> *"Quotes from a source document are limited to 125 characters"*

따라서 "지문 그대로 복붙"은 도구상 불가능하다. 가져올 수 있는 것은
**사실 정보**(제한사항, 입출력 형식, 예제 데이터, 시간/메모리 제한)뿐이다.

### (2) 지문 전문 복제는 하지 않는다

백준 문제 지문은 출제자의 저작물이다. 전문을 복제해 파일로 만들지 않는다.
대신 **교차 확인한 조건을 내 말로 정리**하고, 원문을 읽을 수 있는 **출처 링크**를 남긴다.
사용자가 그 링크에서 직접 복사해 넣는다 (파일에 붙여넣기 자리를 HTML 주석으로 표시).

## 4. 문제 하나당 작업 절차

1. **검색** — 지문을 *텍스트로* 옮겨 적은 블로그를 찾는다 (스크린샷만 있는 글은 제외).
   검색어 예: `백준 <번호> <제목> 문제 "입력" "출력" 지문`
2. **교차 확인** — 독립 출처 **2~3곳**을 fetch 해서 제한사항·예제를 대조한다.
   값이 엇갈리면 그 항목은 `출처 미확인` 으로 표기하고 넘어간다.
3. **레퍼런스 구현** — 정답 코드를 직접 작성한다.
4. **교차검증** — 완전탐색(작은 입력) 또는 다른 알고리즘과 **최소 1,000케이스** 비교.
   불일치 0개를 확인한 뒤에만 기대 출력을 파일에 쓴다.
5. **테스트 케이스 생성** — 아래 극단 입력 체크리스트를 돌며 5~6개 + 대용량 생성기.
6. **파일 작성** — `12865_평범한배낭.md` 형식 그대로.

### 극단 입력 체크리스트

- 요소 0개 / 1개
- 제한 최대값 (N, 값 범위 모두)
- 제한 최소값
- 꽉 찬 경우 / 완전히 고립된 요소
- 모서리·경계 (격자면 네 꼭지점)
- 중복값
- **제한사항의 두 상한이 서로 모순될 수 있는 조합** (예: 12865 는 W 상한 = K 상한이라 W > K 인 물건이 들어올 수 있다)
- 답이 0 / 음수 / 오버플로 경계

## 5. 파일 형식 (엄수)

`12865_평범한배낭.md` 를 그대로 따른다. 섹션 순서:

```
# BOJ <번호> — <제목>

| 항목 | 값 |          ← 번호 / 제목 / 티어 / 시간 제한 / 메모리 제한
## 문제                    ← HTML 주석으로 "원문 붙여넣기 자리" 표시 + 조건을 내 말로 정리
## 입력                    ← 입력 형식만
## 출력
## 제한                    ← 불릿으로 범위만
## 예제 입력 1 / 예제 출력 1
## 추가 테스트 케이스       ← "### 케이스 N" + 입력 블록 + 기대 출력 블록
## 대용량 테스트 케이스     ← 생성기 코드 + (명령, 기대 출력) 표
## 출처                    ← 링크 목록 + "검증 상태"
```

### 절대 쓰지 않는 것 — 힌트 금지

사용자가 **풀기 전에** 읽는 파일이다. 아래는 유형/풀이를 노출하므로 **넣지 않는다.**

- `유형`, `알고리즘 분류`, `태그` 행이나 섹션
- 각 테스트 케이스가 **무엇을 검사하는지** 설명하는 칼럼·문장
- 「주의할 점」, 「함정」, 「이 경우를 빼먹으면」 류의 안내
- 반례의 **오답 원인** 해설 ("262가 나오면 ~한 것")
- 풀이 과정 / 결과 & 근거 / 구상 체크리스트 (이건 블로그용 별도 템플릿)
- 자료구조·알고리즘 이름 (`배낭`, `다익스트라`, `세그먼트 트리` 등)

**단, 제목은 예외다.** 제목에 알고리즘 이름이 들어가도 그대로 상단에 둔다
(사용자 결정 — 기존 백준 지문 형식과 비슷해 읽기 좋다는 이유).

### 검증 상태 표기

파일 하단에 반드시 넣는다. 정직하게 쓴다.

```
- 제한사항 : 독립 출처 N곳 일치
- 예제 입출력 : 독립 출처 N곳 일치
- 시간/메모리 제한 : N곳에서 확인
- 티어 : 출처 미확인 (solved.ac 도 백준 종료와 함께 확인 불가)
```

**추측으로 URL 을 만들지 않는다.** 실제로 fetch 해서 내용을 확인한 링크만 쓴다.

## 6. 배치 계획

문제당 도구 호출 5~7회 → 35문제면 **175~245회**. 한 번에 하면 품질이 떨어진다.

| 배치 | 수량 | 유형 |
|---|---|---|
| 1 | 5 | 자료구조 응용 5 ← **여기서 형식 확정** |
| 2 | 5 | 자료구조 응용 3 + DP 2 |
| 3 | 5 | DP 4 + 그래프 탐색 1 |
| 4 | 5 | 그래프 탐색 5 |
| 5 | 5 | 최단경로 4 + 이분탐색 1 |
| 6 | 5 | 이분탐색 3 + 투포인터/누적합 2 |
| 7 | 5 | 투포인터/누적합 2 + 그리디 3 |

배치마다 파일을 전달하고 형식 피드백을 받는다. **1배치 후 형식이 확정되면 2~7은 빠르다.**

이미 완료: **12865 평범한 배낭** (DP/배낭) → DP 배정분 6개 중 1개 소진. 남은 DP는 5개.
