# SWEA 22759, 묶음 판매 (실패)

# 문제 소개

[문제 사이트 하이퍼링크](https://swexpertacademy.com/main/code/problem/problemDetail.do?contestProbId=AZK3fpuaBJwDFAXk)

편의점을 운영하는 점장인 당신은 음료수를 묶음 판매하고자 한다. 묶음판매란 X개의 음료수를 묶어서 한 세트로 판매하는 것이다. 고객이 음료수를 사고 싶다면 X개짜리 세트를 사거나, 1개짜리 단제품을 구매할 수 있게 된다. 당신은 이제 이 X의 값을 정하고자 한다.

적절한 X 값을 정해보기 위해 당신은 고객의 입장에서 생각을 해 보기로 하였다. 고객이 편의점에 들어와서 음료수 N개를 사고 싶다고 해 보자. 당연히 묶음 판매되는 것을 많이 살수록 이득일 것이므로, 고객은 ⌊N/X⌋(N을 X로 나눈 몫)개의 묶음 세트를 사고, N mod X (N을 X로 나눈 나머지)개의 단제품을 구매할 것이다.

그런데 구매할 단제품의 개수가 너무 많으면 일일이 담기 번거로우므로, 차라리 묶음 제품을 하나 더 구매하는 것이 나을 수도 있을 것이다. 당신은 **N mod X가 X/2 이상이면** 고객이 단제품 N mod X개 대신 음료수 X개짜리 묶음 세트를 하나 더 구매할 것이라고 생각한다.

당신은 고객 분석을 통해, 모든 고객은 항상 편의점에 들어가는 순간 L개 이상 R개 이하의 음료수를 구매하고 싶다는 것을 알게 되었다. 당신은 X의 값을 잘 정하여, 모든 경우(즉 N이 L 이상 R 이하인 모든 R-L+1가지의 경우)에 대해 고객이 단제품 대신 묶음 세트를 하나 더 구매하는 자연수 X가 존재하는지를 판단하려고 한다.

**[입력]**

첫 번째 줄에 테스트 케이스의 수 T가 주어진다.

각 테스트 케이스는 하나의 줄로 이루어지며, 두 개의 정수 L과 R (1 ≤ L ≤ R ≤ 109)이 공백 하나를 사이로 두고 주어진다.

**[출력]**

각 테스트 케이스마다, 모든 경우에 대해 고객이 단제품 대신 묶음 세트를 하나 더 구매하는 자연수 X가 존재하면 “yes”를, 존재하지 않는다면 “no”를 출력한다.

| 입력 예제 | 출력 예제 |
| --- | --- |
| 3
1 2
3 4
100 150 | no
yes
yes |

2번 예제: X = 5이 가능하다.

3번 예제: X = 170이 가능하다.

위에 명시한 X 외의 가능한 X가 존재할 수 있다.

**입력**

| 3
1 2
3 4
100 150 |  |
| --- | --- |

**출력**

no

yes

yes

# 풀이 과정

- 작은 수 L부터 반복문을 돌릴까 하다가, 안 되는 경우를 판단하는 게 더 빠를 것 같았다.
- L%X, R%X가 X/2 미만이면 안 되는 거라고 생각했는데, 최대 10⁹까지 돌아야 했다.
- 탐색 알고리즘이 필요할 것 같았지만 감이 안 잡혀서 20분에 포기했다.

```cpp

#include<iostream>

using namespace std;
/*
 * 음료수를 묶음 판매!
 * - X개짜리 세트를 사거나, 1개짜리 단제품을 구매
 *
 * 고객이 편의점에 들어와서 음료수 N개를 사고 싶다고 해 보자.
 * 당연히 묶음 판매되는 것을 많이 살수록 이득일 것이므로, 고객은 ⌊N/X⌋(N을 X로 나눈 몫)개의 묶음 세트를 사고,
 * N mod X (N을 X로 나눈 나머지)개의 단제품을 구매
 * (묶음을 최대한 구매 + 단제품으로 채우기)
 *
 * 그런데 구매할 단제품의 개수가 너무 많으면 일일이 담기 번거로우므로, 차라리 묶음 제품을 하나 더 구매하는 것이 나을 수도 있을 것이다.
 * 당신은 N mod X가 X/2 이상이면 고객이 단제품 N mod X개 대신 음료수 X개짜리 묶음 세트를 하나 더 구매할 것이라고 생각한다.
 * (그냥 묶음 하나 더 구매하기)
 *
 * 모든 고객은 항상 편의점에 들어가는 순간 L개 이상 R개 이하의 음료수를 구매하고 싶다는 것을 알게 되었다.
 * 당신은 X의 값을 잘 정하여, 모든 경우(즉 N이 L 이상 R 이하인 모든 R-L+1가지의 경우)에 대해
 * 고객이 단제품 대신 묶음 세트를 하나 더 구매하는 자연수 X가 존재하는지를 판단하려고 한다.
 * 제시된 예시 외에 + 명시한 X 외의 가능한 X가 존재할 수 있다.
 */
int main(int argc, char** argv)
{
	int test_case;
	int T;

	cin>>T;
	for(test_case = 1; test_case <= T; ++test_case) {

		int l, r;
		cin >> l >> r;

		// 작은 수인 l 부터 반복문.

		// 안되는 경우의 수를 판단하는 게 더 빠를 거 같은데.
		// 즉 묶음 제품 + 단제품으로 구매하는 경우가 존재하는 경우.
		// 즉 L%X, R%X 의 값이 X/2 미만인 경우.
		// 최대 10^9 까지 순회하게 된다.

		// 탐색 알고리즘이 필요할 거 같은데..

		// 20분 포기. 감도 잡히지 않아.

		int x = r;

		while (x < 100000000) {

			if ((l-l%x) >= x/2 && (r-r%x) >= x/2) {
				cout << x << "일 때 모두 묶음을 하나 더 구매합니다" << endl;
				cout << "이 때의 나머지: " << l%x << ", " << r%x << endl;
				break;
			}
			x++;
		}

	}
	return 0;//정상종료시 반드시 0을 리턴해야합니다.
}
```

# 결과 & 근거

**실패 (20분 포기)**

- 조건을 통과하려면 L~R 구간 전체가 어떤 블록 하나의 "위쪽 절반" 안에 들어가야 한다. 그래서 `R < 2L`이면 X = 2L로 가능하고, 아니면 불가능하다.
- X/2는 실수 나눗셈이다. 정수 나눗셈이었다면 예제 `1 2`가 X=3으로 yes가 돼버린다.
- 10⁹ 제약 + 여러 테스트 케이스는 탐색이 아니라 O(1) 수식으로 풀라는 신호였다.

```cpp
#include<iostream>

using namespace std;

int main(int argc, char** argv)
{
	int test_case;
	int T;

	cin>>T;
	for(test_case = 1; test_case <= T; ++test_case)
	{
		int l, r;
		cin >> l >> r;

		/*
		 * "N mod X ≥ X/2" = N이 자기 블록 [qX, qX+X) 안에서 "위쪽 절반"에 있다는 뜻.
		 * L~R 연속 구간이 전부 통과하려면, 구간 전체가 어떤 블록 하나의 위쪽 절반 안에 들어가야 한다.
		 *   (블록을 넘어가면 다음 블록의 0, 1, 2...에서 바로 실패하니까)
		 *
		 * 1) 가장 쉬운 선택: X = 2L.
		 *    그러면 X/2 = L이고, N이 L ~ 2L-1이면 N mod X = N ≥ L 이라 전부 통과.
		 *    → R ≤ 2L-1, 즉 R < 2L 이면 yes.
		 *
		 * 2) R ≥ 2L이면 어떤 X도 안 된다.
		 *    위쪽 절반의 길이는 X/2 이하 → 구간 길이 R-L+1 ≤ X/2.
		 *    그리고 L은 위쪽 절반 안에 있으니 L ≥ X/2.
		 *    둘을 합치면 R-L+1 ≤ X/2 ≤ L → R ≤ 2L-1. 그러니 R ≥ 2L이면 no.
		 *
		 * L ≤ 10^9 → 2L ≤ 2*10^9 < 2,147,483,647 이라 int 범위 안이다.
		 */
		if (r < 2 * l) cout << "yes" << '\n';
		else cout << "no" << '\n';
	}
	return 0;//정상종료시 반드시 0을 리턴해야합니다.
}
```

> N mod X ≥ X/2가 되려면 L~R 구간 전체가 한 블록의 위쪽 절반에 들어가야 하고, 그게 가능한 조건은 R < 2L뿐이다. 10⁹ 제약을 보고 탐색을 버리는 게 핵심.
